# Contributing

Contributions should improve learning outcomes, correctness, or maintainability.

## Content changes

- Prefer mechanisms and tradeoffs over product marketing.
- Label time-sensitive claims and link primary documentation.
- Include an exercise or concrete example when introducing a new concept.
- Distinguish measured evidence from personal recommendations.
- Avoid claiming that one framework or provider is universally best.

## Code changes

- Never commit credentials or private data.
- Keep examples small enough to understand without a framework.
- Add or update tests for deterministic logic.
- Document any API call that can create cost or external side effects.

## Pull requests

Explain:

1. The learning gap being addressed.
2. What changed.
3. How the content or code was checked.
4. Any time-sensitive assumptions.
